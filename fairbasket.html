A narrow problem, a practical workflow

From shopping decisions to accountable evidence.

Small community organisations often buy the same essentials with limited time and budget. Comparing pack sizes, sellers, delivery conditions and changing prices is tedious. FairBasket keeps the offer, source, decision and later audit trail connected.

01

Define a community need

Set quantities and a spending ceiling for an essential-goods basket. The app never receives or moves donated funds.

02

Compare actual offers

Reuse Onde compro? search to find direct product pages. Distinguish listing/API values, product-page metadata, published ranges and unverified search snippets.

03

Preserve the evidence

Generate a SHA-256 digest for each evidence record, export the audit bundle, and optionally anchor the digest on Base Sepolia with a wallet-signed transaction.

04 · Web3 accountability layer

Anchor a digest on Base Sepolia

Wallet-signed testnet transaction · no purchase funds move through this app.

TESTNET
Demo mode. Connect a wallet, switch to Base Sepolia and provide a deployed contract address to write a real testnet transaction.
Only hashes, a public campaign identifier and the declared amount/type are written on-chain. Never put names, addresses, private donation details or unredacted receipts in public evidence payloads.
  1. Open Remix IDE and create a Solidity file from the contract source in this repository.
  2. Compile with Solidity 0.8.24 or newer, below 0.9.0. In Deploy & Run choose Injected Provider and switch your wallet to Base Sepolia.
  3. Deploy FairBasketRegistry. Use testnet ETH only. Copy the deployed address into the field above.
  4. Connect the same wallet that deployed the contract, select a non-demo evidence record, then publish it. The wallet must approve each transaction.

Base Sepolia uses chain ID 84532. Deployment and writes require testnet ETH for gas; this prototype does not send mainnet transactions.

Trust by design

Web3 is a verification layer, not a buzzword.

The product remains useful if nobody connects a wallet. A testnet transaction is an optional tamper-evident anchor, not a claim that the source price is correct or that delivery occurred.

Evidence stays inspectable

Each record exports its payload, source link, timestamp and digest. Reviewers can reproduce the SHA-256 hash as well as check any on-chain transaction.

Privacy before publicity

Personal details and unredacted receipts do not belong on a public chain. The contract stores a digest, type and declared amount only; the source record is reviewed separately.

Impact claims are measurable

We do not claim savings, partner adoption or deliveries from fictional data. A pilot will measure comparable line-item costs, comparison time and evidence coverage.
